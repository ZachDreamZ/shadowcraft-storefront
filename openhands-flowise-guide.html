How to build custom MCP tools for OpenHands and Flowise without crashing your agents

If you're building autonomous systems using the latest open-source frameworks like OpenHands (an AI software engineer) or Flowise (visual AI workflows), you eventually need to give them access to your custom internal databases and APIs.

The standard way to do this is by building a custom Model Context Protocol (MCP) server. However, integrating these servers can turn into a nightmare of silent failures.

The 3 Silent Killers of Custom MCP Servers

  1. Raw Exceptions = Infinite Loops: If your custom tool throws a bare Python exception instead of returning a proper JSON-RPC McpError, the agent framework often swallows the error. OpenHands might enter an infinite retry loop, wasting tokens and execution time.
  2. Schema Validation Failures: If your inputSchema is missing a required type field, the tool simply vanishes from the agent's available tool list. There is usually no error logged.
  3. Latency Drops: If your tool makes an unprofiled database query that exceeds 5 seconds, the LLM client drops the connection.

How to route multiple tools into OpenHands

If you have multiple MCP servers (e.g., one for Postgres, one for Slack, and one custom internal API), managing the configuration files for OpenHands can be tedious.

Instead of manually managing the routing, you can use the MCP Server Toolkit. It acts as a universal router that sits between OpenHands and your custom tools, handling JSON-RPC traffic, validating schemas, and preventing infinite retry loops when a tool fails.

from mcp_router import MCPRouter

router = MCPRouter()
# Install core servers
router.install_all()

# Route a tool call to your internal DB safely
result = router.route("postgres", "query", {
    "sql": "SELECT * FROM users LIMIT 10"
})
